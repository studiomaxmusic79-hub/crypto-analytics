# Krypta — криптоаналитика

Рабочее веб-приложение на русском: **BTC/USDT и ETH/USDT**, публичные котировки Binance, свечной график, экспериментальные прогнозы на 1 и 4 часа, журнал и проверка результатов. Приложение не запрашивает ключ Binance, не подключает биржевой аккаунт и не совершает сделки. Нет платных API или вызовов ИИ.

**Статус:** проект подготовлен к Render, но не опубликован. Аккаунты и облачные ресурсы не создавались. Исходная база пуста: результаты начнут появляться после завершения горизонтов реальных прогнозов.

## Быстрый запуск на компьютере

1. Установите Python **3.12** (проверенная версия 3.12.14).
2. Распакуйте архив. На Windows запустите `run-windows.cmd`, на macOS/Linux — `bash run-local.sh`.
3. Откройте **http://127.0.0.1:8000**. Терминал оставьте открытым. Остановка — Ctrl+C.

Скрипт создаёт окружение внутри папки проекта и устанавливает зависимости. Локально используется файл `data/crypto.db`. Не удаляйте его, если хотите сохранить историю. При закрытом приложении новые прогнозы не создаются; при следующем запуске проверка старых продолжится.

Ручной запуск:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей строки:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Если порт занят, замените 8000 на 8001. `.env.example` — образец; приложение не читает `.env` автоматически. Переменные задаются в терминале или в панели хостинга.

## Публикация на Render: бесплатный вариант

Здесь необходимы **ваши аккаунты GitHub, Render и бесплатная PostgreSQL-база**. Подписка ChatGPT не нужна приложению во время работы. Его работа после публикации не зависит от включённого ноутбука.

### 1. Подготовьте постоянную базу

- Откройте [Neon](https://neon.com/) и создайте проект на **Free**, без перехода на платный план. Выберите европейский регион, если доступен.
- В **Connect** скопируйте PostgreSQL connection string. Подойдёт стандартная или pooled-строка с `sslmode=require` (дополнительные параметры Neon сохраняйте).
- Это **пароль базы**, а не ключ Binance. Вставляйте его только в секретную переменную Render. Не публикуйте в GitHub и не добавляйте в исходники.
- Бесплатный Neon имеет лимиты хранения и времени вычислений; следите за ними в панели. Выход за лимит Free может остановить работу. Проект не включает автоматического платного расширения. Альтернативно можно использовать любую собственную доступную PostgreSQL-базу.

На Render приложение **откажется запускаться без PostgreSQL**, чтобы не создавать ложное ощущение сохранности SQLite-файла.

### 2. Добавьте проект в GitHub

Создайте новый репозиторий. Загрузите в его корень содержимое папки проекта: `app/`, `tests/`, `render.yaml`, `requirements.txt`, остальные текстовые файлы. Убедитесь, что `render.yaml` лежит в корне, а не внутри дополнительной папки. Локальные `data/`, `.venv/` и реальные пароли загружать нельзя; они исключены в `.gitignore`.

### 3. Создайте веб-сервис

1. Откройте [панель Render](https://dashboard.render.com/).
2. Выберите **New → Blueprint**, подключите репозиторий.
3. Проверьте, что создаётся только один **Web Service** с тарифом **Free**, без платных дополнений.
4. В запрашиваемую переменную **DATABASE_URL** вставьте строку подключения к своей PostgreSQL-базе.
5. Запустите развёртывание. При первом старте таблицы создадутся автоматически, существующие данные не удаляются.
6. После успешного развёртывания откройте выданную Render ссылку вида `https://…onrender.com`. Эту ссылку можно отправить другу.

Ручное создание **New → Web Service** вместо Blueprint:

| Поле | Значение |
|---|---|
| Runtime | Python |
| Region | Frankfurt, если доступен |
| Instance Type | **Free** |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 1 --no-server-header` |
| Health Check Path | `/healthz` |
| PYTHON_VERSION | `3.12.14` |
| DATABASE_URL | Секретная строка PostgreSQL |

Используйте **один worker**. Проверка и генерация работают внутри процесса, отдельный платный worker/cron не нужен. Не удаляйте и не заменяйте базу при повторном развёртывании. Новая версия кода должна использовать ту же `DATABASE_URL`. Для будущих изменений схемы понадобятся отдельные миграции; текущая версия создаёт одну стабильную таблицу.

### 4. Проверьте публикацию

- `/healthz` возвращает `{"status":"ok"}` — соединение с базой работает.
- На главной появились реальные цены обеих пар; предупреждений о SQLite нет.
- В течение первого рабочего цикла (обычно до 30 секунд плюс запросы Binance) появляются прогнозы, если Binance доступен из региона сервера.
- Через час первые прогнозы 1ч получают результат, через четыре — 4ч.
- После **Restart / Redeploy** журнал остаётся. Открыв сайт после сна, дождитесь проверки ожидающих записей.
- При недоступности Binance отображается ошибка; демонстрационные цены не подставляются. Ограничения Binance по региону/IP могут действовать и для облачных серверов. Проверьте доступность до дальнейшего использования; не обходите ограничения.

## Ограничения бесплатного хостинга

Условия проверены по документации 15.10.2026; перед публикацией сверяйте актуальные планы.

- Бесплатный Render засыпает после **15 минут без входящих запросов**; первый запрос после сна может загружаться около минуты. Фоновые исходящие запросы к Binance не гарантируют непрерывную работу.
- Во сне/при остановке сервиса новые прогнозы **не создаются**. Приложение не придумывает их задним числом. После запуска проверяет уже сохранённые записи по историческим свечам в точный целевой момент. Фактическое время проверки может быть позже целевого.
- Проверка идёт партиями до 100 записей за цикл. При большом накоплении результатов потребуется несколько циклов. Недостающие свечи и сетевые ошибки остаются в ожидании и проверяются повторно.
- **Локальный диск Render временный**: SQLite там не используется. PostgreSQL отделён от веб-сервиса и сохраняет записи при его рестартах/развёртываниях, пока база существует и доступна.
- Бесплатная PostgreSQL от **самого Render истекает через 30 дней**, поэтому она не выбрана основным способом долговременного хранения. Neon Free не имеет такого пробного срока, но имеет собственные лимиты и условия.
- У Render есть квоты времени работы, трафика и сборок; бесплатный хостинг не гарантирует работу 24/7. Проверяйте лимиты/настройки расходов в аккаунте и не подключайте платные планы без отдельного решения.

## Прогноз и проверка

**Техническая эвристика `technical-v1`, не обученная модель. Проверенной вероятности успеха нет.** Прогнозы экспериментальные, результат не гарантирован. Приложение не утверждает наличие торговой прибыльности.

1. Для 1ч используются последние **100 закрытых 15м свечей**, для 4ч — **100 закрытых 1ч свечей**. Пропуск или устаревшие входные данные блокируют создание прогноза.
2. EMA12/EMA26 и RSI14 рассчитываются по фиксированному окну; ATR14 — среднее последних 14 истинных диапазонов; импульс — изменение закрытия за 4 свечи.
3. `T = tanh((EMA12−EMA26)/max(ATR, price×0.00001))`.
4. `M = tanh(momentum%/max(ATR%,0.001))`; `R = clamp((RSI−50)/25, −1, 1)`.
5. Итоговый `S = 0.5T + 0.3M + 0.2R`. **Сила направленного сигнала** = `round(|S|×100)`. Даже 90/100 **не означает** 90% вероятности. У WAIT низкая сила означает отсутствие направленного сигнала.
6. Фиксируем нейтральную зону `δ = max(0.12%, 0.5×ATR%)`. Прокси движения `P = S×ATR%×2` — вспомогательное правило классификации, не ценовая цель. Если `|S| < 0.25` или `|P| ≤ δ`, выбираем WAIT; иначе знак S задаёт UP/DOWN.
7. Опорная цена — закрытие последней доступной 1м свечи. Горизонт начинается от границы её закрытия, **не от времени записи**. Время записи и опорное время сохраняются и показываются отдельно. Допустимое отставание опоры при записи — до 2 минут. Цель — граница опорного времени +1ч / +4ч.
8. Факт — закрытие минутной свечи с `closeTime = due_at−1ms`, запрашиваемой по точному историческому времени. Текущая цена после сна не используется вместо целевой.
9. Фактическое изменение `r = (target/base−1)×100`: `r>δ → UP`, `r<−δ → DOWN`, иначе WAIT. Попадание = точное совпадение классов. Направленный прогноз внутри нейтральной зоны считается неподтверждённым.
10. Новая запись — максимум одна на `(пара, горизонт, 15-минутный слот)`. Уникальность обеспечивает база, включая конкурентные вставки. Первичные поля не обновляются; после завершённой проверки результат больше не меняется.

Статистика UP/DOWN и WAIT разделена и считается по выбранной паре и горизонту. Показывается размер выборки; при нуле проверок процент не выдумывается. Перекрывающиеся горизонты зависимы. Это не независимый статистический эксперимент и не оценка прибыли с комиссиями/проскальзыванием.

**Исторический бэктест не запускается и не выдаётся за реальные прогнозы.** После сна оцениваются только записи, действительно созданные до целевого времени; будущие/формирующиеся свечи отфильтровываются при генерации.

## Интерфейс и обновления

- Цена обновляется каждые 15 секунд; свечи, журнал и статистика — каждые 30 секунд, пока вкладка видима. На сервере общий короткий кэш и ограничение частоты запросов.
- Свечи: 15м / 1ч / 4ч. Масштаб — кнопки +/− или колёсико; сдвиг — перетаскивание мышью/пальцем. Наведение показывает OHLC. Последняя свеча может формироваться и выделена прозрачностью; в прогноз не попадает.
- Переключение BTC/ETH, фильтр горизонта, страницы журнала, экспорт CSV. Время отображается в часовом поясе устройства; база хранит Unix milliseconds UTC.
- Адаптивные размеры для телефона, клавиатурные фокусы, состояния загрузки/ошибки/устаревших данных. Нет обязательных внешних шрифтов, CDN или трекеров.
- Общая история публична всем посетителям сайта. Пользовательских аккаунтов нет. HTTP API доступен только для чтения; посетитель не может создавать/редактировать прогнозы.

## Сохранение и резервные копии

CSV в интерфейсе — экспорт результатов, **не полная резервная копия** базы. Не переносите историю редактированием CSV.

- Локально: остановите приложение, скопируйте всю папку `data/`; для восстановления верните её перед запуском.
- PostgreSQL: используйте экспорт/резервную копию в панели провайдера или `pg_dump` в custom format. Пароль вводите безопасно, не записывайте строку подключения в репозиторий. Для восстановления используйте новую пустую базу и `pg_restore`, затем укажите её `DATABASE_URL`. Проверяйте восстановление отдельно. Не импортируйте недоверенные SQL-дампы.
- Тариф Free не заменяет собственную резервную копию. Удаление/истечение срока базы удалит историю вне зависимости от приложения.

## Разработка и тесты

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
node --check app/static/app.js
node --check app/static/chart.js
```

Node нужен только для необязательной проверки JavaScript; для запуска приложения достаточно Python. Тестовые данные существуют только внутри тестов/временных баз и не выводятся вместо публичного рынка.

Стек: FastAPI + HTTPX, SQLAlchemy + psycopg, PostgreSQL на Render, SQLite локально, HTML/CSS/JavaScript и собственный Canvas-график. SPA-сборка не нужна.

| Файл | Назначение |
|---|---|
| `app/market.py` | Публичный Binance, проверка данных, кэш и rate limit |
| `app/analytics.py` | Индикаторы, классификация и оценка результата |
| `app/storage.py` | Неизменяемые прогнозы, история, статистика |
| `app/service.py` | Генерация и восстановление проверок после остановки |
| `app/main.py` | HTTP API, жизненный цикл и статический интерфейс |
| `app/static/` | Русский адаптивный интерфейс и свечной график |
| `render.yaml` | Бесплатный Web Service, подключение существующей PostgreSQL |

Диагностика: `/api/status`, `/api/history`, `/api/stats`, `/api/forecasts`, `/api/market`, `/api/quote`, `/openapi.json`. Не используйте много процессов или копий приложения без отдельного планировщика. Первичные прогнозы защищены уникальностью, но несколько циклов будут излишне нагружать Binance.
